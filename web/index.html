METHOD & LIMITATIONS

Make every check inspectable.

A small experiment in documentation-grounded generation and feedback-driven repair.

01

An explicit contract

You specify the interface, address, destination, and next hop. The checker compares the result with these values. Natural-language context is not independently converted into a verified intent.

02

Grounded generation

A local BM25 retriever ranks built-in notes and passages from enabled imported documents. In live mode, the model receives retrieved text and source IDs. The generation-only baseline receives no retrieved documents.

03

Independent checks

A restricted template renderer, command parser, and explicit intent comparisons inspect the candidate across three parameter sets. The AI does not decide whether its own answer passes.

04

Bounded repair

In live mode, structured checker errors go back to the model for another candidate. The process stops on success or the repair limit. In demo mode, repair uses a known reference template.

What a green result means

The candidate passed this prototype's local checks for the tested inputs. It is not a guarantee that FRRouting accepts it, that the next-hop device exists, or that end-to-end traffic succeeds.

The next research milestone is a version-pinned virtual-router lab with actual command loading and packet tests, followed by a larger held-out benchmark. PDF ingestion, multi-vendor support, IPv6, VLANs, and arbitrary network tasks are outside this first version.

YOUR FIRST LIVE EXPERIMENT

From a demo to real generation

  1. Connect your model using the form.
  2. Open the template lab and choose Live AI.
  3. Start with Retrieval + repair and a repair budget of 1.
  4. Inspect the generated template and each independent check.
  5. Export the evidence, including the model, references, errors, and token usage.

A successful connection confirms access to the model, not compatibility or generation quality. A live run checks those next. Generation uses API credits. A budget of 1 allows up to two model calls.

WHAT IT CHECKS

Evidence sequence

  1. Each peer is reachable on its directly connected subnet.
  2. Each remote loopback is unreachable before its candidate route.
  3. FRRouting accepts the generated configuration.
  4. Kernel routes and interface addresses match the intent.
  5. ICMP reaches every peer loopback after loading.
